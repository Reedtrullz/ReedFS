# Heading references

Physical quaternion yaw, AP/LNAV/flight-director guidance, coordinate-derived route tracks and saved headings use **true north**. Default PFD/MCP headings and selected bugs carry `T`; telemetry and route tracks explicitly say TRUE. A runway number is not a surveyed bearing.

The Heading reference control changes presentation only. Magnetic values carry `M SFC`, including selected bugs. Changing reference, date or location does not rotate the aircraft or change the persisted true AP target. An MCP heading step rounds the displayed target, applies the step and converts once through a required reference tag: east-positive variation D gives M=T−D and T=M+D, wrapped to 0–360 degrees. Untagged, grid, nonfinite or magnetic-without-variation commands reject. The coordinate-only FlightPlan adapter remains true; currently unconsumed RFMS `Runway.magneticCourse`, `LandingData.course` and `ProcedureLeg.courseDeg` are not guessed or converted. A future consumer needs a separate documented source/reference boundary.

Magnetic presentation uses committed scenario UTC and geodetic position with **0 km above the WGS84 ellipsoid**, on the ground and in flight. This is a surface estimate, not an aircraft-height or MSL/geoid correction. A one-entry exact-position/UTC cache bounds storage; true presentation does not calculate the magnetic field. The display preference is separate from flight state, defaults to TRUE at application startup and is not saved in scenario snapshots. The snapshot version and physical identities remain unchanged.

WMM2025 is valid from 2025-01-01 through 2029-12-31 (exclusive 2030). Decimal year uses the actual UTC year length, including leap years. There is no older/nearest-model substitution. Invalid location/time, geographic poles, unsupported epochs or horizontal field below 2000 nT show a reason and TRUE headings, and disable magnetic MCP heading edits. Field 2000–below6000 nT shows a visible caution and `!` on magnetic values. Grid reference is unavailable. The generic numeric calculation accepts explicit ellipsoid heights −1 to100 km; that qualification domain does not extend the UI surface policy.

## Sources and rights

Model ID: `wmm-2025/noaa-legacy-harmonics/v1`. The generic spherical-harmonic implementation is a typed port of NOAA's public-domain [legacy C algorithm](https://www.ngdc.noaa.gov/geomag/WMM/data/WMM2020/WMM2020LegacyC.zip), archive SHA256 `1572cbf708be7cbd544bb70684cc4fb8a786c0e663a4bdbeaa21dc7d67053a90`. It uses the current 2025 coefficients, rather than the legacy archive's 2020 model. No third-party npm port or dependency is adopted.

The 90 degree/order coefficient rows come from the [pinned CIRES WMM.COF](https://raw.githubusercontent.com/CIRES-Geomagnetism/wmm/96dc367e360aae21e4077ac4a54d019b32aff7f8/wmm/coefs/WMM.COF), SHA256 `06791cd95faba7bdf4a709808f2715a53fe689b29c23b9886bc2196fa9b3eb13`, header `2025.0 WMM-2025 11/13/2024`. [NOAA's WMM product page](https://www.ncei.noaa.gov/products/world-magnetic-model) identifies its information/software as public domain; US Government material is distinguished here from the repository's MIT-authored code. Current [NOAA accuracy and limitations](https://www.ncei.noaa.gov/products/world-magnetic-model/accuracy-limitations-error-model) supply the 2000/6000 nT policy, rather than obsolete legacy-driver thresholds. Model errors, local crustal fields and disturbances remain separate from implementation precision.

Twelve independently printed [NOAA test rows](https://www.ncei.noaa.gov/sites/default/files/2025-02/WMM2025_TEST_VALUES.txt), SHA256 `ae289c94e2200e4deeae2dfdedf543a8a0e93096512b30d6a754199731f570d0`, are retained as numeric facts in the test fixture: 2025.0/2027.5, 0/100 km ellipsoid height, northern/equatorial/southern points. Raw longitude240° is mapped to equivalent−120°. X/Y/Z/H/F are checked within half their printed0.1nT unit, and inclination/declination within half their printed0.01° unit. These checks establish implementation correspondence; they do not establish operational navigation or compass accuracy. Grid variation and annual-rate columns are not qualified by these tests.

## Acceptance boundaries

Unit/UI checks cover independent numeric rows, leap/date limits, poles/dateline/invalid input, weak-field boundaries, reference-tag refusal, nonzero one-conversion MCP steps and unchanged physical/AP/FD/route/weather/generation/save state on presentation changes. Native acceptance must use actual browser-worker progress and matching cohort, visible controls and headings, pause/date/save behavior, and unchanged original handling/visual gates. Local tests, CI, canonical deployment and ordinary public acceptance are distinct receipts. Aircraft-height/geoid support, imported avionics consumers, polar grid reference, operational navigation, physical devices and continuous full flight remain outside this increment.
