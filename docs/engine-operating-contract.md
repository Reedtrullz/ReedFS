# Engine idle, fuel cutoff and weather

Throttle zero requests running idle while fuel is available and the corresponding fuel cutoff is off. The left and right fuel commands are independent pilot controls; autopilot thrust commands do not reopen either fuel supply. A cutoff immediately sets combustion thrust and fuel flow to zero while the existing N1/N2 spool-down continues. Empty tanks have the same combustion boundary. Reopening fuel uses the existing simplified automatic spool model, including at idle; this does not implement a starter, ignition, relight envelope or start sequence (#108).

The Engine fuel disclosure in Takeoff setup exposes a separate cutoff toggle for each engine. Throttle changes and Set takeoff config preserve those commands. New saves retain both commands; older saves with absent fields normalize to fuel on without rewriting their bytes. Malformed nonboolean commands are rejected at the save/worker boundary. Running saves still restore paused.

`atmosphereForDensityAltitude` now lives in the atmosphere module; aero retains its compatibility re-export. Aero and engines use the same scenario surface-pressure/temperature offset on the ISA profile. This is an approximation, not a measured vertical weather sounding. Engine Mach uses air-relative speed and the shared local speed of sound. The existing ISA altitude/Mach thrust table is multiplied by weather density divided by ISA density at that altitude, avoiding applying altitude lapse twice. Zero weather deviation preserves the original table output. Shutdown EGT uses local ambient temperature.

This relative-density thrust correction is a gameplay engineering estimate, not a measured CFM56 temperature/pressure lapse map. Existing idle/spool/SFC/EGT/table constants remain explicitly gameplay-calibrated in the FDM shell and source-governance register. No temperature-dependent spool constants, derates, quantitative manufacturer limits, or reverser model are invented. #69 retains their source qualification; #73 retains reverser work. #132 separately migrates derived/display/autopilot airspeed quantities to this atmosphere.

Verification covers settled idle, per-engine cutoff despite full throttle, fuel depletion, hot/cold and sea-level/high-altitude consistency, integration wiring, boolean validation, legacy saves and unchanged invalid bytes. Actual browser-worker comparison forbids fallback and checks the complete result against synchronous stepping; visible native fuel controls are exercised independently. Existing takeoff/approach/MCP/physics/performance limits remain required regressions. These are software contracts, not source-qualified aircraft performance or physical cockpit acceptance.
