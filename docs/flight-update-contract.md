# Flight-aware app updates

The app explicitly registers the generated Workbox service worker. A new build waits and offers an update. A running session cannot activate it through the update control. **Later** keeps the flight and makes the offer available again. There is no controller-change handler that automatically reloads unsaved flights.

**Save session and update** uses the existing origin-locked save action, creates a unique new slot, and waits for confirmed completion. Failed/quota/denied saves preserve the old collection and pending export payload; activation is refused. Immediately before activation and again before reload, the exact stored snapshot must match the current paused/stopped session, excluding only its save timestamp. A resumed, changed, cancelled or unrecovered invalid flight is preserved without reload. Activation has one bounded ten-second wait, with listener/timer cleanup and no retry loop. A cancelled successful save may remain as a recovery slot.

The generated service worker uses separate Workbox cache IDs for each build cohort, precaches bundled Cesium code/fonts and the physics worker, and does not claim other open tabs. Existing controlled tabs retain their own cached code. Remote terrain/imagery/METAR remain network sources; an offline bundled shell/worker is not an offline airport scenery pack. Older cohort caches remain until explicit origin-data removal; quota/retention UX is tracked in #87. There is no custom service-worker/cache implementation.

Worker protocol2 stamps every request, result and error with the compiled app build cohort. A worker rejects a mismatched request before execution. The app rejects a mismatched response before publication and uses the finite validated main-thread fallback from the immutable dispatch snapshot. The diagnostic export distinguishes configured runtime, observed matching worker cohort, and last validated execution backend. Direct synchronous calls remain on the validated fallback path.

The installed Chromium integration uses two actual builds with explicitly synthetic identities (`a` repeated40 times and `b` repeated40 times); these are fixtures, not real commit receipts. It covers active-session deferral/cancellation, verified unique save, quota failure, reload/restore, a second continuing tab, offline reload with HTTP cache cleared, and an actual old-worker protocol-error reply followed by validated main-thread recovery. Separate existing worker/full-flight lanes retain their acceptance; this is not physical mobile, external scenery or complete airport-offline qualification.
