# Route coordinate boundaries

Imported flight plans and runway route starts must have finite latitude in [-90, 90] and longitude in [-180, 180]. The existing complete flight-plan validator also protects the store and route adapter. Rejected imports throw before the immutable store updater returns; aircraft, route, controllers, simulation time and revisions remain unchanged. Runway endpoints remain optional, as in the existing dataset.

Enroute interpolation, route distance/bearing and route projection now share shortest-path spherical geometry with the existing nominal radius of 6,371,000 m. A 179/-179 equatorial leg goes east across two degrees. A high-latitude leg may pass over a pole. Coincident points have no unique bearing; zero is a deterministic convention and existing waypoint capture sequences duplicates. Exact antipodal legs have no unique shortest direction and produce an explicit unavailable-guidance reason; interpolation rejects them. Near-coincident interpolation avoids dividing by a vanishing sine.

This nominal sphere is an approximation. It is not an ellipsoidal geodesic, navigation certification, or runway survey. The two existing regional training routes retain their former local-model lengths within 0.1%. Two independent published WGS84 examples bound long-route distance differences to 0.6% for those holdouts; this is not a proof of that bound for every route or bearing. All supported ordered runway pairs must still satisfy the existing finite/compatible route matrix. Short-runway local offset calculations remain unchanged within their existing dataset envelope.

Physics continues to use its existing WGS84 ECEF/ENU transforms. Only the demonstrated exact-axis inverse defect changes: an ECEF pole returns finite latitude, conventional longitude zero and height above the existing polar radius. The ECEF origin has no defined geodetic position and throws. Existing near-pole and regional round trips remain tested; no broader deep-Earth inverse claim is made.

Primary reference for WGS84 parameters, published independent distance examples and nonunique coincident/antipodal directions: [GeographicLib examples](https://geographiclib.sourceforge.io/html/python/examples.html) and [geodesic definitions](https://geographiclib.sourceforge.io/html/python/geodesics.html). Only numeric reference facts are used; no new runtime library or source dataset is imported.

The native qualification is explicitly seeded and uses an actual physics worker with fallback forbidden. It checks parity, finite in-range positions, short dateline/polar guidance, duplicate sequencing, controlled antipodes and rejection without mutation. It supplements existing flight/route regressions; it does not establish continuous full flight or physical-device acceptance.
