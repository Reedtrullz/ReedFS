# Committed instrument observations

The PFD's aircraft pose, airspeed, altitude/QNH, radio altitude, flight phase, FMA, managed speed and flight-director guidance use one immutable simulation commit. Immediate MCP selections remain visible in the explicitly selected target strip and bugs. Changing QNH, an AP mode or a route while a worker result is pending cannot recompute observed flight data against an older aircraft state.

The PFD exposes its committed step index as a diagnostic DOM attribute. A visible `FLIGHT DATA` strip labels current, waiting, stale, paused, preview or invalid data and its wall age. Its 250 ms timer continues when physics does not publish, so silence cannot look like a freshly connected instrument. Data older than one second is stale while running. A paused simulator is labeled paused, and unrecovered numerical failure is invalid; the retained last valid values do not become a new observation. Reset and scenario restoration clear the old commit and show preview/waiting until a new validated step. Camera interpolation does not participate.

The first implementation covers the current local PFD. Companion owner loss and reconnection add their explicit validity source when #148/#116 land; this strip does not infer connection health from a local pause. Future cockpit instruments in #63 reuse the committed observation contract. Physical device readability and refresh acceptance remain separate from the bounded Chromium rendering test.

Tests reproduce an uncommitted QNH altitude jump and verify selected targets remain immediate while observed altitude/airspeed/FMA stay on the prior commit. A real Chromium worker with fallback forbidden supplies the rendered instrument fixture. A delivery barrier tests unchanged readouts/step, waiting then stale age, simultaneous publication of new mode/altitude, visible strip bounds and distinct pause state. That lane is instrument integration rather than seeded or continuous-flight qualification.
