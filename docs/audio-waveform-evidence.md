# Native engine waveform qualification

The selected Chromium suite renders the current two-engine synthesizer at fixed N1 values20/40/60/80/100 through actual OfflineAudioContext, OscillatorNode and GainNode implementations. Each mono render has exactly12,000 samples at48kHz (0.25seconds, at least17 cycles at the slowest tested frequency). Metrics retain duration, finite data, peak, RMS and largest adjacent-sample change; increasing N1 must increase RMS. No waveform hash is an acceptance oracle.

The current source has maximum per-engine gain0.12, engine bus0.8 and master1. Its nominal coherent two-engine peak ceiling is0.192. A0.24 qualification ceiling allows25percent for band-limited waveform overshoot while retaining substantial mixer headroom below full scale. Nonzero profiles must exceed RMS0.002 to detect missing delivery; intentionally requested master zero has a separate exact-silence test. Sample jumps above0.24 fail the current bounded oscillator profile. These are declared current-content limits; changed audio content needs a measured review of the profile rather than silently raising bounds.

The lane also renders three native failure controls: a silent engine bus, an excessive bus gain, and a constant source switching from-0.18 to+0.18. The discontinuity control stays below the peak ceiling and fails the jump criterion independently. Every failure control must be rejected for the corresponding reason, so an accidentally permissive numerical oracle cannot pass by reporting finite output alone.

Browser queue, caption, mute/reset, context suspension/resume and node-teardown acceptance remain in `rfs-audio-session.spec.ts`; controlled browser speech transport is explicit there. Offline PCM proves numerical rendering under the declared source profile. It does not prove human listening quality, physical headset/mobile behavior, spatial camera audio or consistent platform speech voices. Listening checks accompany changed content/cameras in #86 and the supported-device contract in #103.
